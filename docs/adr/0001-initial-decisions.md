# ADR-0001：v1 上传中继基线

状态：已批准（Owner）  
日期：2026-11-08

## 决策
- 本地显式 HTTP 代理 `127.0.0.1:18585`，针对 R2 UploadPart 执行 TLS MITM，原程序使用合并 CA；其他流量透传。
- 本地将完整 UploadPart 请求体缓冲于内存并计算 MD5，先查询 VPS。
- VPS HTTPS 使用 8443，优先 HTTP/2 连接复用。
- 数据缓存唯一键为 MD5，相同内容可跨 UploadId 复用字节，不复用不同 R2 目标的任务结果。
- VPS 磁盘缓存首次完整写入起固定 1800 秒，内存索引，重启扫描缓存文件名恢复索引，无数据库。
- R2 请求使用原始预签名 URL，额外最多重试 3 次；VPS 不可用时本地直传。
- 不拦截或控制 Multipart 完成请求。

## 原因
本地上行约 100 Mbps，是主要瓶颈；VPS 出口标称 1000 Mbps。目标是避免相同分片失败重试时再次消耗本地带宽，并利用 VPS 可复用缓存执行 R2 PUT。

## 已接受取舍
- 不做 MD5 碰撞保护或同 MD5 首次并发消重。
- 30 分钟到期不延寿，可能影响超时未完成的 R2 重试。
- 无数据库，重启后不恢复进行中的 R2 请求。
- 未接管合并，因此不能独立感知合并失败或自动修复全部 Multipart 流程。
- 原客户端的请求超时不由代理修改。

修改本 ADR 必须同步需求 ID 和验收测试。

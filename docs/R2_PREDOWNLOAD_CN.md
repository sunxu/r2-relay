# R2 Relay Predownload：本地预置文件前置匹配（v1）

状态：实现 PR，**默认关闭**；未合并、未部署时不影响生产。

## 行为

- 开启 `[download.predownload] enabled = true` 后，Mac 端 R2 Relay 启动时建立 `~/.cache/r2-relay/predownload/`（新建目录权限 `0700`）。已有文件和目录不清理；目录不允许是符号链接。
- `download.backend = "remote"` 和 `"local"` 共用同一前置检查。下载入口先按原始 R2 URL 对象键最后一段（URL 解码后的文件名）查找预置目录内**同名普通文件**；不存在或是符号链接则直接进入当前下载后端，**不会额外请求 R2**。
- 仅在文件存在时，使用相同 URL、原始端到端请求头发起**独立的 GET**，只取响应头，不读取响应体，随后关闭该连接。探测读超时 5 秒、连接超时 3 秒；探测不可用即回退原后端，避免长时间阻塞接管。
- 原始响应为 `200` 且有唯一合法 `Content-Length`，与本地文件全长相同，则使用本地文件正文流式交付；原始响应为单区间 `206`，校验请求 Range、响应 `Content-Range` 与 `Content-Length`，以 `Content-Range` 的对象总大小核对本地文件全长，再按响应字节范围返回本地文件对应片段。
- 原始响应为错误状态、长度不一致/未知、压缩响应、Range 不合法、网络探测异常，均关闭探测 GET 并进入原有后端。原后端选择及算法不变；当文件存在但匹配失败时，允许额外一次 GET。
- 本地命中返回**真实 R2 HTTP 状态与端到端响应头**，复用现有 `DiskResponseServer` 去除逐跳头和统一正确 `Content-Length` 的规则。原始文件按只读文件描述符和 `pread` 流式返回，不改动、不删除；中途读取失败则中断响应，不伪造成功 EOF。

## 配置

```toml
[download.predownload]
enabled = false
```

## 已知边界

- 此方案仅用**同名与大小**判断命中，不验证内容哈希或版本；不同 Key 的同名同大小文件可能被误命中，返回的 ETag 也可能与本地正文不对应。这是用户选择的简化策略，需要自行保证预置内容正确。
- 完整对象文件与单 Range 206 支持；多 Range、无有效长度或非 identity 编码不命中。
- `remote` 命中时不创建 VPS 下载任务；未命中时才调用原 VPS 后端。`local` 命中时不执行 Local Range 分片。两者均不会改变 iota-tools。
- 只有开启 Predownload 时才会创建并检查预置目录。Predownload 探测连接不读取正文，但上游网络和 TCP 缓冲可能仍产生少量正文流量，不能承诺零上游正文流量。

## 测试

`cd local && python -m pytest -q`：覆盖双后端同名命中、未命中无 GET、200/206、响应头、文件长度不符、压缩/错误状态、异常回退、符号链接拒绝、文件替换竞态、原文件保留。Mock 测试不代表真实 R2 验收。

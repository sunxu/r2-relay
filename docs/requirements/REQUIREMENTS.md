# R2 Relay 需求规格

版本：v1.0（2026-11-08）  
状态：Owner 已确认的需求基线；RC1 离线实现已合并 `main`（PR #15，Merge Commit `18e068a923238bccb83b2e8a77fe25ac4f7abb32`）；真实 VPS/R2 生产验收仍待完成。**RLY 编号、要求与既定设计约束未改变。**

## 目标与流量
原始 Python/aiohttp 程序经显式 HTTP 代理上传 Cloudflare R2 Multipart Upload 的分片。代理读取完整 HTTPS PUT 请求体计算 MD5，与 VPS 进行缓存协商：首次上传分片字节到 VPS，命中后不再传输字节。VPS 将缓存分片上传到原预签名 R2 URL，把 R2 实际响应返回原调用方。目标负载：100 个约 10 MB 分片；本地上行 100 Mbps，VPS 线路 1000 Mbps；性能目标是在可靠条件下尽量跑满本地上行。

## 硬性需求

| ID | 优先级 | 要求 |
|---|---|---|
| RLY-001 | P0 | 本地 Python 显式 HTTP/HTTPS 代理监听 `127.0.0.1:18585`，支持 CONNECT、对目标 R2 HTTPS MITM。 |
| RLY-002 | P0 | 仅为 R2 `UploadPart` PUT（包含 `uploadId` 和 `partNumber`）执行缓存流程；其他请求按普通代理透传，不管理合并。 |
| RLY-003 | P0 | 调用方启动时将原有 CA 与代理 CA 合并；保持 TLS 验证，目标站证书有正确 SAN。 |
| RLY-004 | P0 | 目标 UploadPart 请求必须先完整读取进本地内存、再根据请求字节计算 MD5、查询 VPS；有全局内存预算与合法大请求直传路径。 |
| RLY-005 | P0 | VPS 内容缓存的唯一键为小写十六进制 MD5，不使用其他字段判断缓存 HIT；不专门处理同 MD5 首次并发写入和恶意 MD5 碰撞。 |
| RLY-006 | P0 | 本地→VPS 使用 HTTPS 连接池，优先 HTTP/2，VPS 监听 8443；MISS 才传分片正文，HIT 不传正文。 |
| RLY-007 | P0 | VPS 磁盘保存原始分片，完整发布后立即安排该请求的 R2 PUT；不同 R2 请求保留独立原 URL/签名上下文。 |
| RLY-008 | P0 | 缓存从首次完整写入 VPS 起固定保留 1800 秒；命中与重试均不续期；到期停止命中并删除。 |
| RLY-009 | P0 | VPS 缓存索引与上传任务状态在单 Python 进程内维护，不使用数据库；重启扫描磁盘文件名，恢复尚未到期的完整 MD5 缓存文件。 |
| RLY-010 | P0 | VPS 使用当前请求的 R2 预签名 URL 执行 UploadPart，针对暂时性失败最多额外重试 3 次；失败后返回最终错误，不能伪造 R2 200/ETag。 |
| RLY-011 | P0 | 本地代理向原始 aiohttp 返回 R2 实际 HTTP 状态、ETag、必要端到端响应头和正文；过滤逐跳 HTTP 头。 |
| RLY-012 | P0 | VPS 不可用时本地代理改为直接上传原 R2 URL；R2 本身的业务错误不能误判成 VPS 不可用。 |
| RLY-013 | P0 | 合并、取消和 ListParts 均不由本系统接管；原始业务自行调用 CompleteMultipartUpload。 |
| RLY-014 | P0 | R2 请求每次携带当前 URL 和签名头；缓存内容跨 UploadId 可复用，但对应 R2 PUT 的执行结果不可跨不同目标盲目复用。 |
| RLY-015 | P1 | 记录缓存命中、传输字节、耗时、R2 状态与重试、回退原因；允许在受控运行日志中显示完整敏感参数。 |
| RLY-016 | P1 | 按 4/8/16 等并发比较端到端吞吐、失败率及内存，力争本地可用上行利用率≥90%，不保证物理链路一定能达到。 |
| RLY-017 | P1 | 生产 VPS 部署由 Owner 指定完整 Commit SHA，通过 GitHub Actions 校验目标属于 main 且部署专项 CI 通过后，使用独立、无密码的部署系统账号及 SSH Forced Command 执行固定 Root 接收器（sudo 仅允许不带额外参数的固定 Root receiver，部署锁文件必须 root-owned 且权限受限），完成版本化安装（已存在版本必须通过完整性校验后复用）、原子切换、服务健康检查与失败回滚；Push/PR 合并不得自动部署，部署范围不得修改 Caddy、凭据、缓存或其他服务。 |

## 已确认的简化与限制
- MD5 视为可信的字节缓存标识；不做跨租户碰撞防御或额外键匹配。
- 同一个 MD5 的首次并发请求不设计专门的消重协议；由此导致的重复写入或覆盖属于已接受边界，但不得让未完成文件被当作完整 HIT。
- 不使用数据库，不恢复重启前内存中的请求、连接和执行任务；只恢复有效缓存文件索引。
- 缓存固定过期，不因活跃上传延寿；过期后尚未重新打开缓存的 R2 Worker 可能失败。
- 不监听、不控制 CompleteMultipartUpload。若外部合并失败且外部未重新发起 UploadPart，本系统不能自行感知或主动修复；有新 UploadPart 时可复用仍有效的字节缓存。
- 预签名 URL 的有效期独立于 VPS 缓存期限；过期的 URL 不能被 VPS 延期使用。
- 原始 aiohttp 超时/取消可能发生在 VPS 重试完成前；不修改原始业务超时设置。
- 非目标 HTTPS 原样隧道传输；目标域名同一 CONNECT 内的非 UploadPart 也需正确转发。

## 部署参数
本地监听 `127.0.0.1:18585`，VPS HTTPS `:8443`（443 已占用）；VPS 地址、TLS 证书、Token、缓存容量与路径由部署环境提供，不提交真实密钥。
